Night Shift that stays on

Unplug a monitor or let the display sleep, and the warm filter is gone. Night Shift still says "on", but the screen has lost its warm tint. nightshift-fix brings it back automatically.

Why it happens

Every time the display configuration changes (plugging or unplugging a monitor, screen sleep, system wake), macOS resets the displays' gamma tables. CoreBrightness, the service that drives Night Shift, sometimes fails to re-apply its filter afterwards. The "on" state stays, but the filter is gone. That's why toggling Night Shift off and on by hand usually fixes it.

It's most likely when changes stack up, for example when you unplug a monitor while the display is asleep.

How it works

1 · Listensfor display changes and screen sleep/wake.
2 · Rememberswhether Night Shift was on before the change.
3 · Waits 2 sfor the displays to settle.
4 · Restoresthe filter with a quick off/on toggle, but only if it was on before.

It never changes your schedule, color temperature or anything else. It uses the same system class, CBBlueLightClient, as Control Center.

Install

Requires Xcode Command Line Tools (xcode-select --install).

git clone https://github.com/hugomach/nightshift-fix.git
cd nightshift-fix
./install.sh

The script compiles the helper into ~/.local/nightshift-fix/, registers a LaunchAgent and starts it right away. After that it starts automatically at every login.

Verify

launchctl list | grep nightshift-fix   # PID = running
tail -f ~/Library/Logs/nsfix.log       # unplug/replug a monitor

Each time the filter is restored, the log gets a line nsfix: re-applying Night Shift.

Uninstall

From the repo folder:

./uninstall.sh

Or manually, without the repo:

launchctl bootout gui/$(id -u)/com.user.nightshift-fix
rm ~/Library/LaunchAgents/com.user.nightshift-fix.plist
rm -rf ~/.local/nightshift-fix ~/Library/Logs/nsfix.log

Nothing is left behind, and your Night Shift settings are untouched.

What goes where

FAQ & troubleshooting

Does the log grow forever?

It isn't rotated automatically, but it's tiny: one ~80‑byte line per event, roughly 0.5 MB a year even with heavy use. Delete it any time with rm ~/Library/Logs/nsfix.log.

The filter still disappears

Check that the helper is running and look at the log. If your monitor wakes slowly, increase the 2 * NSEC_PER_SEC delay in src/nsfix.m and run ./install.sh again.

The screen flickers briefly

That's expected. The quick off/on toggle is what restores the filter.

It stopped working after a macOS update

CBBlueLightClient is a private Apple API. Uninstall the helper and open an issue.
